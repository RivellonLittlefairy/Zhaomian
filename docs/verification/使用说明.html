过客哨 · 使用说明

采用前台检测；新图片同步保存到系统相册 Pictures/PasserWatch，App 内保留查看副本。

GPU 与 CPU 对比

默认“GPU 优先”，目标 20 FPS。停止时可切“CPU 对比”；开始后看各模型实际后端、实际 FPS 与总耗时。GPU 不可用会回退 CPU，需看页面状态，不根据开关名称判断已加速。对比细节。

开始使用

  1. 安装 app/build/outputs/apk/debug/app-debug.apk（调试版本）。
  2. 允许相机权限；拒绝后可在页面点击“授予相机权限”或“打开应用设置”。
  3. 固定摆放手机，调整后置画面的观察区域。
  4. 点击“开始检测”，保持 App 在前台，检测时屏幕自动保持亮着。
  5. 连续确认可见人脸，或者完整身体出现（脸模糊也可以）后，保存一张 JPG 到相册；停留时不追加。
  6. 画面持续无人至少 2 秒后重新待命，下次出现再存一张。

查看和停止

点击最近图片看大图；查看时会停止检测，关闭后需重新点击开始。退后台、锁屏或旋转也会结束本次监测，返回后不会自动开始。

页面同时显示监测状态与保存状态。停止不会取消已经接收的少量写入任务；“已保存”只在写入完成后出现。

相机被占用或画面无法恢复时，停止后点击“重试相机”。

图片和存储

新抓拍同步写入系统相册 Pictures/PasserWatch，App 私有 filesDir/captures 保留查看副本。原来的私有图片不会自动迁移到相册。卸载或清除数据删除私有副本；系统相册照片通常保留。Android 10 起无需存储授权，Android 7–9 需点击“授予相册保存权限”。

空间不足时显示保存暂停，检测仍继续。释放空间后点击“恢复保存”，错过的图片不补存。手机空间不足时应清理其他可删除文件；本版尚无图片清理界面。

同时最多保留 1 张正在写入和 2 张等待；过载提示本次未保存。文件保存失败不会为同一次出现反复拍摄。

理解第一版的规则

按画面的一次有人出现去重，不逐个人计数。A 仍在时 B 进入不会再拍；启动时已有人也可触发。极快经过、暗光和遮挡可能漏检，机位和照明会影响效果。

模型随 APK 打包，断网可工作。不含推送、录像、身份识别、跨线计数、后台或锁屏监测。

debug APK 有“调试：手动保存当前帧”按钮，只在没有检测和没有保存任务时可用；正式界面会隐藏此按钮。
