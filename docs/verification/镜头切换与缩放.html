使用方法

  1. 覆盖安装新版 APK，打开实时哨兵页，相机就绪后查看「镜头与缩放」。
  2. 下拉选择自动后置或系统实际开放的物理镜头。切换会停止检测并重新绑定，等相机就绪后手动开始。
  3. 使用缩放滑块或常用倍率按钮，检测运行时也可以调整缩放。数值来自 CameraX 的真实 ZoomState。
  4. 切页、重试或重新打开 App 后镜头选择仍保留；相机重新绑定时缩放采用 CameraX 默认值，通常为 1×。

镜头选择逻辑

从 ProcessCameraProvider.availableCameraInfos 获取后置相机，再从 physicalCameraInfos 获取其开放的物理镜头；不猜测厂商隐藏 ID。CameraSelector 根据逻辑 ID 筛选；物理 ID 通过 Camera2Interop.Extender 分别设置到 Preview、ImageAnalysis、ImageCapture 三个 builder，再进行绑定。

标签根据焦距与传感器尺寸估算 35mm 等效焦距，区分超广角、广角 / 主摄和长焦；是估算值。元数据缺失时显示普通镜头标签与 ID。

自动后置由系统决定物理镜头，缩放不保证切到长焦。物理选择请求固定对应输出镜头，但具体支持仍受 Camera HAL 限制。

缩放逻辑

通过 CameraControl.setZoomRatio 调整，按 ZoomState 的 minZoomRatio / maxZoomRatio 限制范围。滑块采用对数分布，使设备最大倍率很高时，低倍率仍容易精细调整。常用倍率仅显示在真实支持范围内的按钮。

新的滑块请求取消较旧请求属于正常过程，不作为错误报告；实际失败会提示。缩放和相机状态观察者在关闭时解除，避免切镜头、切页后残留。

倍率相对于当前所选相机，不等于手机原生相机的统一焦段标尺。高倍率可能是数字裁切，清晰度可能下降；使用较高倍率也可能让完整身体移出视野。

错误与验证

某个物理镜头如果无法同时支持预览、检测和高清拍照，会显示相机启动错误。菜单仍可选择自动后置恢复，不把失败的切换报告成成功。

画面未变化：物理输出配置修正

首次版本仅设置 CameraSelector 的 physicalCameraId，但检查 CameraX 1.4.2 的实际字节码后发现普通单相机绑定路径没有将其传入 UseCase 输出；处理该字段的入口是并发相机 SingleCameraConfig 路径。旧日志 lens=0/3 只记录了应用选择，不能证明长焦输出。

修正为三路 Camera2Interop.Extender.setPhysicalCameraId。此配置进入 SESSION_PHYSICAL_CAMERA_ID_OPTION，并由 Camera2 会话配置展开。新增会话 CaptureCallback 读取返回的物理镜头元数据和焦距，页面会显示输出请求 ID 与元数据状态，日志记录 logicalActive / physicalResults / focal。

逻辑相机 activePhysicalId 不能单独作为每路输出来源的证据。应同时观察三路物理输出配置、返回元数据及实际画面视角变化。若厂商不支持，应报错或继续定位，不把菜单选择当作切换成功。

本次修复 Debug / Release 构建通过（BUILD SUCCESSFUL in 45s），Lint 0 errors / 25 warnings；结果见 docs/build-physical-output-fix-final.log。没有自动安装手机，物理输出仍待实机确认。请覆盖安装后再次从主摄切到长焦，确认视角变窄，查看是否返回物理 3 元数据，再测试保存照片。
