识别异常：物理镜头分析流异常

2026-10-14 · 1× CPU 真机识别与保存已恢复

故障位置

加入自动选镜时，为 Preview、ImageAnalysis、ImageCapture 分别指定了物理相机 ID。手机预览正常，但实际送入模型的 Bitmap 是纯绿色；CPU 和 GPU 均持续推理却无法识别人。更换 RGBA 为 YUV 并显式解码仍然绿色，因此转换格式未解决问题。

绿色输入为 R=0、G=154、B=0，与全零 Y/U/V 经 BT.601 转换的结果一致。这提示分析流没有有效像素，但不能仅凭颜色断言厂商驱动内部具体故障。

修复与验证

仅取消 ImageAnalysis 的物理相机 ID，让分析通过逻辑相机输出 YUV；预览和拍照保留物理镜头绑定。其余识别阈值、模型和抓拍条件保持原设置。

  • 同一台 V2458A、1×、CPU 模式：实际模型输入恢复正常彩色场景，faces=1。
  • 日志记录人脸推理约 10–11 ms，并成功保存 1440×1920 JPEG。
  • 同时观察到 person 和 pose 的非零结果，人员分数最高 0.9609375。
  • 用户确认「这次可以了」。

证据：运行日志、恢复后的实际输入、Debug 和 Lint 构建记录。

原因边界

已定位到本机固定物理相机分析输出路径。移除分析流物理绑定后恢复，说明这套物理输出配置存在兼容性问题。尚未证明是设备 HAL 的输出组合限制、驱动缺陷，还是 CameraX 与物理流配置的交互问题，不能把猜测写成厂商缺陷结论。

本轮验证覆盖 1× CPU。GPU 回归、长焦下逻辑分析与物理预览的视野对齐仍需单独验证；不声称所有镜头组合均已通过。
