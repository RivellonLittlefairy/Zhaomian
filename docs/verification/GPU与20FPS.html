GPU 优先 · 目标 20 FPS

2026-10-13 · 用户要求启用 GPU 并提高到每秒分析 20 帧。

后续修复

2026-10-14 已抓到人员 GPU 输入大小不匹配的错误，改用浮点人员模型。详见 修复记录与 CPU/GPU 速度比较。

改了什么

  • 人脸、人员与身体关键点模型使用 MediaPipe BaseOptions 的 Delegate.GPU，逐模型尝试，不保证所有模型和所有算子都能在 GPU 执行。
  • GPU 创建或推理失败时，仅该模型关闭 GPU 实例并回退 CPU；后续不反复尝试失败的 GPU。CPU 也失败时仍明确报告检测错误。
  • GPU 模型的创建、调用与关闭都在同一个相机分析线程；停止后在每个创建/回退前检查会话，已在原生代码中执行的任务可收尾。
  • 采样时间计划从 200ms 改为 50ms，能在 30 FPS 相机回调中按目标 20 FPS 取样。慢推理时保留最新帧，不积压，也不补跑错过的帧。
  • 页面显示各模型 GPU / CPU / 回退状态、实际完成帧率、总耗时和各模型阶段耗时。UI 指标最多约每 250ms 更新，抓拍规则处理每个有效结果。
  • 保持可见人脸或完整身体才抓拍、连续 2 个有效帧确认、离开 2 秒再待命，以及系统相册保存。分析/保存分辨率保持原配置约 640×480，实际以 CameraX 为准。

怎么比较

  1. 安装最新 app/build/outputs/apk/debug/app-debug.apk，保持同一机位和光照。
  2. 选择“GPU 优先”，开始检测，等模型首次加载完成后观察 10–20 秒。
  3. 看实际 FPS 与总耗时，再分别查看人脸、人员、身体的加速状态。
  4. 停止检测，选择“CPU 对比”，再开始；使用同样的人脸/完整身体场景比较。

有脸时可能只运行人脸模型；没有脸时最多运行三个模型，所以只比较相同分支。首次加载与回退耗时会影响第一帧，不能拿首帧当稳定性能。

20 FPS 是目标采样率，不是已实测吞吐。如果总处理耗时超过约 50ms，相应分支通常达不到 20 FPS。低于 1 FPS 时也显示实际小数帧率，不误报 0。

验证范围

已有本地单元测试用于 GPU 优先、创建失败回退、推理失败释放、停止后不启动 CPU、20 FPS 时间调度及实际帧率。构建与 Lint 见 docs/build-gpu-20fps-final.log。
