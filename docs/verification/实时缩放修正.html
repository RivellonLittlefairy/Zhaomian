定位结果

用户日志确认物理主摄 2 和长焦 3 返回对应元数据，镜头切换已生效。但日志没有记录裁切区域，不能把 CameraX ZoomState 变化当作物理输出实际缩放的证明。

持续拖动不切换的原因明确：旧代码每次取消再延后 250ms，只有停止输入才执行，属于防抖。用户期望的是拖动中持续处理，应该采用节流。

本次修改

  • 固定物理镜头使用应用数字缩放：预览层按倍率放大并中心裁切；分析 Bitmap 和保存照片使用同一中心源区域裁切。
  • 物理镜头内倍率 = 统一倍率 ÷ 原生焦段倍率。比如主摄 1–约 3× 之间会持续改变画面，不再只在镜头阈值发生变化。
  • 逻辑相机回退路径继续使用 CameraControl 原生缩放，应用裁切归零，避免重复放大。
  • 切镜采用节流：当前任务不会被每一个拖动事件取消；跨焦段时在拖动中执行，镜头重绑间隔至少约 180ms。拍照处理中仍延后切镜。
  • 在同一物理镜头内，数字裁切立即更新。缩放条的局部拖动值不因自动切换镜头而重置。
  • 读取 Preview 的实际分辨率与旋转，预览容器按来源比例居中并裁切，避免将黑边一起当作内容缩放。

清晰度与范围

这部分明确是数字缩放，不能增加光学细节。保存照片直接保留裁切像素，不把小图插值回原尺寸；例如 1920×1440 原图做 2× 数字裁切，结果约为 960×720。因此相册中的照片尺寸会随数字倍率下降，实际像素以查看页为准。

达到长焦的原生焦段会切入长焦，数字裁切回到约 1×，重新利用该镜头的光学细节。镜头之间仍有重绑定造成的短暂停顿，本轮不声称达到原生相机无缝切镜。

切换阈值仍读取本机焦距与传感器尺寸，没有固定三倍或固定厂商 ID。元数据缺失及镜头不可用继续降级。
