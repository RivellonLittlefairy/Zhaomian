三页分别改了什么

01 / 实时哨兵

大面积竖向相机画面，真实检测状态 HUD，实际 FPS 和耗时。保留一键开始 / 停止、GPU 优先 / CPU 对比、最近抓拍、保存计数和错误反馈。

停止时可重试相机；Debug 版保留手动拍照。预览中的十字只是构图参考，不表示检测坐标。

02 / 抓拍相册

读取 App 内实际 JPG，按时间倒序排列，支持全部 / 今天筛选、图片数量与占用统计、刷新、复制本地目录路径。

图片懒加载，点「查看原图」打开 App 内查看，再可跳到系统相册。历史私有图片没有相册副本时给出提示。

03 / 规则调优

四个参数滑块接入实际分析、识别和抓拍门控。修改草稿后点击应用；默认值可以恢复。

配置和 GPU 偏好保存到本机，重新打开 App 仍保留。六卡抓拍流程是说明，当前状态与待处理数量来自运行数据。

规则现在可以实际调整

参数默认值 / 范围作用
分析目标帧率20 FPS / 1–30 FPS控制采样频率。实际完成帧率仍取决于相机和推理耗时，并不保证达到目标。
置信度阈值0.60 / 0.30–0.95用于人脸、人员和身体模型的识别阈值。完整身体关键点的有效性规则仍保留。较低阈值更灵敏，也可能增加误检。
连续确认帧数2 帧 / 1–5 帧连续符合抓拍条件才触发一次；无人或检测失败会清零。1 FPS 模式为回调抖动保留少量时间容差，避免每一帧都被误判为中断。
离开确认时长2.0 秒 / 1.0–5.0 秒抓拍锁定后，连续有效无人达到时长才重新待命。

应用参数不会在原生模型推理中途热更新；停止后修改，下一次开始时由新配置创建分析器和模型。单次出现仍只触发一次抓拍。

页面切换与既有功能

后续已增加 镜头切换与实时缩放，详见独立更新说明。

  • 切到相册或规则页会停止检测并释放相机；返回实时页后手动开始，不会悄悄恢复检测。
  • 打开照片也会暂停检测。停止前已入队的保存仍按原逻辑完成；尚未发起的自动拍照按会话检查取消。
  • 相机权限与旧 Android 的相册写入授权继续保留；系统相册查询和打开异常有提示，避免权限变化导致 UI 崩溃。
  • 保留人员 GPU 浮点模型、CPU int8 模型和回退处理；GPU 路径继续不设置会导致原生断言的 person 白名单，而在 Kotlin 筛选人员。
  • 保留可见人脸 / 完整身体抓拍、独立高清照片、系统相册发布与 App 内查看副本。
  • 相机状态观察者在关闭控制器时主动移除，避免频繁切页累计观察者。
