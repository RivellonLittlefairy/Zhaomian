检测小图，保存独立照片

2026-10-14

模糊的主要原因

之前直接保存约 480×640 的检测帧，像素不足，放大后细节丢失。提高 JPEG 质量无法补回不存在的细节。

改动

  • 保留约 640×480 的 CameraX ImageAnalysis 与既有检测模型、采样策略。
  • 增加 ImageCapture，确认可见人脸或完整身体后拍照，目标 1920×1440。实际尺寸根据手机与三路相机流的支持情况协商，竖屏通常转为 1440×1920，不保证恰好该尺寸。
  • 采用低延迟拍照模式；拍照和保存 JPEG 质量均设为 95，维持原来的相册发布和保存成功计数。
  • 拍照后的裁切、旋转和 Bitmap 转换在工作线程执行；照片交给原有有限保存队列。相机图像和失败 Bitmap 均释放。
  • 仅允许一张拍照正在处理。停止后的待发起请求按会话校验取消；停止前已发起的照片允许完成保存。页面释放时解绑三路流并关闭分析线程。
  • 手动保存按钮也改为独立拍照。照片查看显示文件实际像素尺寸；完整查看最多解码约 2048 像素，最近图片使用缩略图。

实际限制

高清照片拍摄发生在检测确认之后，与确认检测帧存在时间差。人员移动较快可能改变构图，独立照片未再次执行三模型审核。增加拍照流也可能影响相机吞吐，当前尚未在目标手机测量。

像素提升主要解决放大后细节不足。暗光、运动模糊、焦点、镜头污渍仍影响清晰度；这次没有强制短曝光或手动对焦。旧照片保持原像素，不会自动变清晰。

验证

Debug / Release 最终构建通过（BUILD SUCCESSFUL in 50s），Lint 0 errors / 21 warnings；输出见 docs/build-high-resolution-photo-final.log。没有自动安装或宣称真机清晰度验证完成。

  1. 覆盖安装新版，先在明亮环境测试静止人员或手动拍照。
  2. 打开新照片，查看照片尺寸是否明显高于旧的 480×640，最好在系统相册放大对比。
  3. 观察检测 FPS 和人员 GPU 状态，以及走动人员的照片清晰度、抓拍时机。
  4. 若仍糊，保留照片原文件与日志中的 camera analysis / photo captured 尺寸，再区分低分辨率、失焦、暗光与运动模糊。
