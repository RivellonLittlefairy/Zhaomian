用户操作

实时页只保留缩放滑块和快捷倍率，显示当前自动选中的镜头及输出元数据。倍率以系统默认后置主摄为 1× 基准；不再把长焦本身的 1× 直接当作整个相机的 1× 显示。

App 根据手机开放的配置自动决定选镜。快捷倍率包含从镜头元数据推导的原生焦段；2×、5× 等普通快捷按钮只是操作捷径，不是硬编码的切镜头阈值。

如何读取配置与决定镜头

  1. 从 CameraX 获取可访问的后置逻辑相机和关联物理相机；不使用固定厂商 ID。
  2. 读取各镜头焦距和传感器物理尺寸，估算 35mm 等效焦距。
  3. 镜头原生倍率 = 镜头等效焦距 ÷ 默认后置相机等效焦距，组成从超广角到长焦的焦段阶梯。
  4. 在可用镜头中选取原生倍率不大于目标倍率、且最接近目标的镜头。没有适合的已知物理镜头时使用系统逻辑相机。
  5. 镜头内缩放倍率 = 用户目标倍率 ÷ 所选镜头原生倍率，再限制到设备报告的支持范围。

例如某设备长焦原生倍率为 2×，在约 2× 进入长焦；另一设备是 5×，则不会在 3× 强行切长焦。当前手机的切换点依据读取的等效焦距比例计算，未将“3×”或 ID“3”写死。

元数据不能用于推导倍率的镜头不参与焦段阶梯。没有可用物理镜头时，保留系统逻辑相机的缩放控制；系统是否切换内部镜头由厂商决定。

切换时的检测与照片

  • 预览、分析和高清拍照三个输出仍通过 Camera2Interop 指定相同物理镜头。
  • 跨过焦段切换点时短暂停止分析帧 intake，解绑旧输出并绑定新输出，缩放应用后恢复分析。
  • 识别模型仍由同一分析线程持有，不因每次自动切镜头重新加载 GPU 模型。
  • 使用分析 epoch 丢弃旧镜头已经在处理、但尚未提交的结果。切换不是“有人离开”的证据。
  • 保留同一检测会话、保存计数和已经触发的抓拍锁定；只清理连续确认计数和离开计时，防止跨镜头拼接确认或无人时间。
  • 拖动请求采用节流，在持续拖动中也执行自动切镜，重绑间隔至少约 180ms；拍照正在处理时延后镜头切换。
  • 物理镜头绑定、打开或缩放失败时回退系统逻辑相机，并在当前控制器中避免再次尝试已失败的镜头。

与原生相机的区别

本方案的切换点由公开焦距与传感器尺寸推导，是焦段估算，未读取厂商原生相机私有的选镜策略。原生相机可能根据亮度、对焦距离、微距、稳定性等选择继续使用主摄；本轮不复刻这些私有策略，也不保证无缝切换。重新绑定输出会有短暂黑屏或停顿。

高于某镜头原生倍率的部分可能仍是数字裁切。镜头是否成功输出，需要结合画面视角变化和返回物理镜头元数据判断，菜单或日志中的请求 ID 不能单独当作成功证明。

设备缺少元数据、限制物理输出、或不支持三路流时，以降级后的实际输出为准。界面显示当前选镜和元数据状态，便于定位。
